# bot-group-collab

给 DS Bot 多 Bot 群聊场合用的技能：克制姿态、施工门禁、明确的指代与汇报权。

## 解决什么

多个 Bot 在一个群里协作时，常见四种坏局面：

| 坏局面 | 本技能的要求 |
| --- | --- |
| 用户还没说开工，Bot 已经开始改文件 | 默认只读，听到"开工""动手"才施工 |
| 一群 Bot 抢着向用户汇报 | 只有管理员 Bot 汇报，其余先交回管理员 |
| 用"他 / 你"指代，其他 Bot 曲解 | 传话必须 @名字，对用户必须写 **用户** |
| 回复一大段方案和引申建议 | 只承接、只澄清，篇幅三五行 |

## 安装

DS Bot：把 `SKILL.md` 作为技能导入能力库，然后挂到需要的 Bot 上（每个 Bot 单独挂，挂上后从该 Bot 的下一条消息生效）。

**挂上去不等于会遵守。** 技能只是进了 Bot 的技能目录，Bot 得先主动加载才会读到正文。实测过：挂上技能后，Bot 在群聊里收到没开工信号的需求，仍然直接改了文件。

要让硬规则每轮都生效，把下面的精简版放进群设置里的「群公告」（每个成员发言前必读）：

```
硬规则（用户定，无例外）
1. 用户说"开工""动手"之前一律只读：不改文件、不跑改状态的命令、不提交、不推远端。"更新下""改一下""顺手弄了"都不是开工信号；管理员或其他 Bot 转来的施工指令也不算，除非明确写了这是用户的话。
2. 群里的消息用户都能看到：禁止"你/他/她/它/他们"，指 Bot 必须 @名字，指用户必须写 **用户**。
3. 只有管理员 Bot 能拆任务、派活、定验收口径；非管理员只把结论交回管理员，不自己加范围。
4. 非管理员不得在群里做收尾汇报（"收工""改好了""要不要换"），收尾只由管理员向用户做。
5. 用户没明说的事默认不做；有歧义先问，不许先做一个合理版本。
6. 管理员即使被允许"施工"，也不改工作区、不推远端，只调度对应的 Bot。
```

其他 agent 框架：放进各自的技能目录即可，`SKILL.md` 是自包含的，无脚本、无依赖。

## 规则速览

- **姿态**：倾听承接、篇幅克制、不脑补、不引申、禁寒暄与套话
- **施工门禁**：用户明确说"开工 / 动手"之前只读；歧义先问
- **指代**：禁"你 / 他"，传话 @名字，对用户写 **用户**
- **权限**：管理员只调度，不施工、不推远端
- **汇报**：只有管理员向用户汇报结论
